# شواهد پیاده‌سازی صفحه ۲۳

## دامنه منبع

صفحه ۲۳ PDF شامل فصل ۱۶ «مرکز تماس و پشتیبانی آنلاین» و فصل ۱۷ تا انتهای بند ۱۷-۱ «اصول مالی» است. الزامات نرم‌افزاری این صفحه بدون تغییر فایل ممیزی اصلی در این سند ردیابی شده‌اند.

## مرکز تماس و پشتیبانی آنلاین

- کانال‌ها: تلفن، چت داخل سامانه، تیکت، پیامک، ایمیل و مراجعه حضوری در مدل تعامل پشتیبانی پوشش داده شده‌اند.
- تیکت دارای کد رهگیری، تاریخچه پیام، پاسخ متقاضی و پاسخ کارکنان است. یادداشت داخلی در API از متقاضی پنهان می‌ماند.
- تماس‌ها و تعامل‌های خارج از پنل با کانال، موضوع، خلاصه، متن پاسخ، مدت، نتیجه، کارشناس مقصد و امتیاز کیفیت ثبت و audit می‌شوند.
- ثبت اطلاعات حساس دریافتی از تلفن، ایمیل، پیامک یا مراجعه حضوری در API رد می‌شود؛ فقط چت و تیکت احراز هویت‌شده داخل سامانه مجاز هستند.
- ارجاع تخصصی بدون انتخاب کارشناس فعال و دارای نقش تخصصی پذیرفته نمی‌شود.
- UI متقاضی قواعد پاسخ‌گویی، ممنوعیت وعده خلاف واقع، کانال امن اطلاعات حساس، مسیر شکایت، آموزش مدارک، کد رهگیری و هشدار پرداخت رسمی را نمایش می‌دهد.
- UI کارکنان امکان پاسخ مستند، تعیین وضعیت تیکت و ثبت کامل تعامل و کیفیت را دارد.

## نظام مالی، درگاه پرداخت و کنترل وجوه

- تعرفه قانونی و هزینه خدمات به‌صورت دو فیلد مستقل مدیریت و جمع آن‌ها در سرور محاسبه می‌شود.
- API پیش‌فاکتور قبل از پرداخت، پرونده و خدمت، مبالغ تفکیکی، جمع، وضعیت درگاه و هشدارهای ممنوعیت کارت‌به‌کارت/کارکنان/حساب واسط را برمی‌گرداند.
- دسترسی پیش‌فاکتور و رسید برای متقاضی به مالک پرونده محدود است و فقط نقش‌های مالی و نظارتی مجاز به مشاهده گسترده هستند.
- شروع پرداخت در حالت غیرفعال یا sandbox متوقف می‌شود و در حالت production نیز تا تکمیل آداپتور PSP رسمی هیچ پرداخت ساختگی ایجاد نمی‌شود.
- پرداخت‌ها به پرونده متصل هستند، snapshot مبالغ تفکیکی دارند و برای پرداخت موفق رسید الکترونیکی یکتا و audit مشاهده رسید صادر می‌شود.
- گزارش مالی تجمیعی برحسب وضعیت و روند ۹۰ روزه فقط برای نقش‌های مالی/نظارتی ارائه می‌شود.
