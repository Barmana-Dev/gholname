# شواهد پیاده‌سازی صفحه ۴

مبنای این سند، صفحه ۴ فایل «طرح توجیهی کارگزاری ثبتی» و بندهای ۶-۱ تا ۶-۹ است. این تغییر فقط کنترل‌های نرم‌افزاری همان صفحه را پوشش می‌دهد.

## پوشش الزامات

- برای هر ۹ خدمت، داده‌های اختصاصی در API اعتبارسنجی و به‌صورت رمزگذاری‌شده در پرونده نگهداری می‌شود.
- تفکیک عرصه و آپارتمان دارای مدل ساختاریافته قطعات/واحدها، شناسه، طبقه، کاربری و مساحت است و تعداد آن با تعداد اعلام‌شده تطبیق داده می‌شود.
- تجمیع و افراز، چند پلاک، مالکان/ذی‌نفعان و شرح سهم را به‌صورت ساختاریافته ثبت می‌کند و تطابق تعداد پلاک‌ها در API اجباری است.
- تغییر وضعیت، تعیین حدود و اصلاح سند دارای توضیحات، موقعیت/حدود و مندرجات فعلی و صحیح مستقل هستند.
- پرونده متصرفان قانونی، سابقه و مبنای تصرف، استشهادات، تعهد اصالت، اعلام تعارض منافع و اعلام سند مشکوک را اجباری می‌کند.
- درج ادعای ماده ۱۰، طرف‌های پرونده، مستندات ادعا، تعهد اصالت و گزارش امضاشده کارشناس را پیش از تبادل یا تکمیل اجباری می‌کند.
- صدور المثنی و ادعای ماده ۱۰ هر دو رضایت/تعهد الکترونیکی قابل audit دارند و بدون آن ثبت نهایی رد می‌شود.
- انواع مدارک مجاز و مدارک الزامی هر خدمت در API تعریف شده‌اند؛ UI فقط همان انواع را ارائه می‌کند و ارسال نهایی تا تکمیل مدارک معتبر مسدود است.
- تکمیل خدمت به گزارش امضاشده کارشناسان متناظر وابسته است. خدمت متصرفان علاوه بر گزارش ثبتی و نقشه‌برداری، کنترل ریسک ثبت‌شده می‌خواهد.
- مجوز بارگذاری، حذف و ارسال نهایی در پاسخ API محاسبه و همان مجوزها در UI اعمال می‌شود. متقاضی فقط پرونده خود و در وضعیت قابل ویرایش، کارشناس فقط پرونده ارجاعی و ناظر فقط نمای فقط‌خواندنی دارد.

## آزمون‌های مرتبط

- `server/src/page04-services.test.ts`: پوشش هشت خدمت، مدارک الزامی، مدل تفکیک، چندپلاک/ذی‌نفع، کنترل حساس متصرفان و ماتریس اقدام نقش‌ها.
- `server/src/validation.test.ts`: اعتبارسنجی داده‌های اختصاصی همه خدمات صفحه ۴ و رد داده ناقص.

اجرای کنترل کیفیت: `npm test`، `npm run typecheck`، `npm run lint` و `npm run build`.
