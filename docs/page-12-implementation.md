# شواهد پیاده‌سازی الزامات صفحه ۱۲

## دامنه بررسی

صفحه ۱۲ فایل «طرح توجیهی کارگزاری ثبتی» به‌صورت متنی و تصویری بازخوانی شد. دامنه نرم‌افزاری این صفحه شامل وضعیت‌های ۴ تا ۱۵ پرونده و ثبت زمان، کاربر، علت و توضیح تغییر؛ پیام‌رسان داخلی کنترل‌شده؛ و امکانات درج‌شده پنل کارشناسان است.

## شواهد فنی

- ۲۴ وضعیت پرونده در `applications.status` تعریف شده و وضعیت‌های سند در میزکار مدیر عملیات/تطبیق/مدیر سامانه قابل انتخاب است. کارشناس فقط وضعیت‌های بررسی، نقص، انتظار متقاضی، تکمیل مدارک و اقدام تکمیلی را می‌تواند ثبت کند؛ همین محدودیت در API نیز اعمال می‌شود.
- علاوه بر کنترل نقش، API گردش مجاز وضعیت را در `canTransitionApplicationStatus` بررسی می‌کند و پرش نامعتبر، بازگشت به پرونده مختومه یا تغییر تکراری را با `409` رد می‌کند. واژگان تکمیلی سند (پرداخت، بررسی کارشناسی، تبادل و بازگشت نقص، توقف امنیتی، لغو و ارجاع شکایت) در `database/migration_009_workflow_completion.sql` و آزمون‌های رگرسیون ثبت شده‌اند.
- هر تغییر وضعیت در `status_history` همراه وضعیت قبلی و جدید، زمان، کاربر اقدام‌کننده، علت الزامی و توضیح اختیاری ثبت و در تاریخچه RTL پرونده نمایش داده می‌شود.
- پیام‌های سیستمی، پشتیبانی، اعلام نقص، هشدار زمان‌بندی، تأییدیه دریافت مدرک، اطلاعیه پرداخت و پیام عمومی به‌صورت نوع‌دار ثبت می‌شوند. نوع پیام مجاز بر اساس نقش در API و UI محدود است تا متقاضی نتواند پیام سیستمی، نقص کارشناسی یا پرداخت را جعل کند.
- بارگذاری موفق مدرک، پیام ماندگار «تأییدیه دریافت مدرک» را با نسخه و ضمیمه همان مدرک در یک تراکنش ثبت می‌کند.
- پیام می‌تواند فقط به مدرک فعال همان پرونده متصل شود. حذف پیام API ندارد و ایجاد پیام در audit زنجیره‌ای ثبت می‌شود.
- دسترسی مستقیم جزئیات، تاریخچه، پیام‌ها، مدارک و خروجی پرونده برای کارشناس ثبتی و نقشه‌بردار فقط در صورت ارجاع فعال مجاز است. پشتیبانی فقط پرونده دارای تیکت و مالی فقط پرونده دارای پرداخت را می‌بیند؛ مالی نیز فقط پیام‌های مالی/سیستمی مرتبط را دریافت می‌کند و ناظر فقط‌خواندنی به مکالمات داخلی دسترسی ندارد.
- پیام متقاضی به کارشناسان ارجاع‌شده یا پشتیبان پرونده اعلان می‌شود. پیام پشتیبانی متقاضی به‌صورت تراکنشی به تیکت باز همان پرونده متصل می‌شود یا یک تیکت کنترل‌شده جدید می‌سازد تا پشتیبان اعلان‌گرفته واقعاً دسترسی مجاز داشته باشد. پیام کارکنان نیز برای متقاضی اعلان ایجاد می‌کند.
- میزکار کارشناس فهرست پرونده‌های ارجاع‌شده، پیوند مشاهده کامل پرونده و مدارک، گزارش کارشناسی اولیه/ثبتی/نقشه‌برداری، اعلام نقص، درخواست اقدام تکمیلی و تاریخچه تغییرات را ارائه می‌کند.

## آزمون مرتبط

`server/src/page-12.test.ts` محدودیت پرونده ارجاعی، مالکیت متقاضی، رابطه پشتیبانی و مالی، مجوز انواع پیام برای نقش‌ها و منع ثبت وضعیت نهایی/ارجاع توسط کارشناس را پوشش می‌دهد. کنترل نهایی پروژه با تست، typecheck، lint و build ریشه انجام می‌شود.
