# شواهد پیاده‌سازی صفحه ۱

## دامنه تطبیق

صفحه ۱ فایل «طرح توجیهی کارگزاری ثبتی» شامل عنوان سامانه غیرحضوری، نام متقاضی، شناسه ملی، شماره ثبت، موضوع فعالیت، مبنای قانونی، مرجع ناظر، نوع طرح، نسخه سند و فهرست مطالب است. فهرست مطالب قابلیت نرم‌افزاری مستقل ایجاد نمی‌کند و اجرای فصل‌های آن در دامنه صفحات بعدی است.

## پیاده‌سازی

- اطلاعات هویتی و مبانی رسمی شخص حقوقی در جدول تک‌ردیفی `organization_profile` با وضعیت پیش‌نویس/منتشرشده، شماره بازبینی، زمان انتشار و هویت آخرین ویرایشگر ذخیره می‌شود.
- API عمومی فقط نسخه منتشرشده را با cache کوتاه‌مدت برمی‌گرداند و در نبود انتشار هیچ شناسه یا داده پیش‌نویس افشا نمی‌کند.
- API مدیریتی خواندن را به نقش‌های مدیر عملیات، تطبیق، ناظر سازمان و مدیر سامانه محدود می‌کند؛ ویرایش و انتشار فقط برای مدیر سامانه مجاز است.
- ویرایش با اعتبارسنجی سخت‌گیرانه شناسه ملی ۱۱ رقمی، شماره ثبت عددی، طول متن‌ها، رد فیلدهای ناشناخته، کنترل هم‌زمانی خوش‌بینانه و ثبت audit انجام می‌شود.
- صفحه «درباره ما» اطلاعات منتشرشده را به‌صورت RTL، واکنش‌گرا و دارای حالت بارگذاری/عدم انتشار نمایش می‌دهد. پنل مدیریت نیز فرم کامل، وضعیت انتشار، حالت فقط‌خواندنی و پیام خطا/موفقیت دارد.
- عنوان و کارکرد درگاه غیرحضوری از قبل در UI عمومی، پنل‌ها و APIهای موجود پروژه برقرار بود و در این تغییر بازنویسی نشد.

## آزمون‌های مرتبط

- `server/src/organization-profile.test.ts`: اعتبارسنجی داده کامل، رد داده ناقص/اضافی، نگاشت امن خروجی و ماتریس دسترسی.
- `client/src/access.test.ts`: اعمال قابلیت‌های دریافتی API برای نمایش یا پنهان‌سازی بخش مشخصات کارگزاری.
- کنترل نهایی: تست‌های صفحه ۱ و دسترسی UI، typecheck و lint کل workspace و build تولید کل workspace.
