# پشتیبان‌گیری، بازیابی و پایش

`npm run backup` از MySQL/MariaDB یک dump تراکنشی و از فایل‌های بارگذاری‌شده archive می‌سازد، بسته را با AES-256 و PBKDF2 رمز می‌کند و SHA-256 ثبت می‌کند. رمز مستقل `BACKUP_ENCRYPTION_PASSWORD` و مسیر `BACKUP_DIR` الزامی‌اند. `database/restore.sh /absolute/path/to/backup.enc --confirm` پس از بررسی رمزگشایی و ساختار archive، دیتابیس و فایل‌ها را بازیابی می‌کند.

در تولید نسخه باید روزانه به مقصد جداگانه منتقل شود. نگهداری پیشنهادی: ۷ نسخه روزانه، ۴ نسخه هفتگی و ۱۲ نسخه ماهانه. secretها و کلید رمزنگاری نباید داخل backup عمومی یا مخزن Git باشند.

مانور بازیابی محلی در دیتابیس ایزوله با بررسی ۳۳ جدول انجام شده است و باید حداقل فصلی در محیط مقصد تکرار شود. داشبورد uptime پردازش، RAM، CPU/load، اتصال و latency دیتابیس، ظرفیت/فضای آزاد دیسک، KPI، صف pending/dead-letter و رخدادها را نشان می‌دهد. شبکه، TLS و سلامت سطح میزبان باید علاوه بر این پایش داخلی با agent زیرساختی کنترل شوند.

در رخداد: ثبت incident، محدودسازی اثر، حفظ log، بازیابی سرویس، تحلیل علت ریشه‌ای و اقدام اصلاحی الزامی است.
