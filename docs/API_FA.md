# راهنمای API

همه مسیرها زیر `/api` هستند. مسیرهای عمومی شامل health، فهرست/جزئیات خدمات و صفحات وضعیت است. مسیرهای احراز هویت شامل register، login، me، logout، ویرایش پروفایل، OTP موبایل و setup/enable/disable MFA است. پرونده، اسناد، عملیات، شکایت و مدیریت به نشست معتبر (کوکی HttpOnly `regbroker_session`) و قابلیت نقش مربوط نیاز دارند؛ درخواست‌های POST/PUT/PATCH/DELETE باید هدر `X-CSRF-Token` برابر کوکی `regbroker_csrf` داشته باشند. `GET /api/health` فقط `{status}` برمی‌گرداند و جزئیات در `GET /api/health/details` با هدر `X-Health-Token` است. ساخت کاربر مدیریتی رمز یک‌بارمصرف تولید می‌کند و برای نقش `admin` به `stepUpOtp` نیاز دارد.

بدنه‌ها JSON هستند، به‌جز بارگذاری سند که multipart است. اعداد فارسی و عربی پیش از validation به رقم انگلیسی تبدیل می‌شوند. خطاهای اعتبارسنجی با وضعیت 400، نبود احراز هویت 401، منع دسترسی 403، نبود منبع 404 و تعارض وضعیت 409 بازگردانده می‌شوند.

هر پاسخ API دارای `X-Request-ID` است. اتصال سازمان ثبت از صف پایدار با شناسه idempotency، claim تراکنشی، retry نمایی، سقف تلاش و dead-letter استفاده می‌کند. payload صف رمزنگاری می‌شود و نتیجه در گزارش API ثبت می‌گردد. آدرس و token واقعی باید مطابق قرارداد رسمی در محیط تنظیم شوند؛ حالت disabled هیچ تراکنش ساختگی تولید نمی‌کند. PSP نیز تا دریافت قرارداد رسمی fail-closed می‌ماند.
