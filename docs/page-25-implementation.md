# شواهد پیاده‌سازی صفحه ۲۵

## دامنه الزام

صفحه ۲۵ سند شامل دو بخش است: «SLA و پایداری ۹۹ درصد» و «مدیریت اسناد، سوابق، لاگ‌ها و پرونده الکترونیکی». موارد نرم‌افزاری قابل اعمال شامل پایش پایداری، تشخیص و ثبت اختلال، گزارش ماهانه، پشتیبان و بازگشت، ثبت رویدادهای الزامی، کاتالوگ بایگانی، محدودیت بیشتر پرونده مختومه و ثبت مشاهده یا استخراج است.

## SLA و پایداری

- نمونه سلامت سرویس، زمان پاسخ، نرخ خطا و وضعیت عملیاتی/اختلال/قطعی در `service_health` ثبت می‌شود.
- داشبورد نظارتی نرخ پایداری ۳۰ روزه، هدف ۹۹ درصد، تعداد نمونه، اختلال، قطعی، میانگین پاسخ، رخداد باز و آمادگی بازگشت را نمایش می‌دهد.
- گزارش ماهانه CSV از مسیر `GET /api/admin/reports/sla.csv?month=YYYY-MM` نرخ پایداری و رخدادهای همان ماه را همراه علت و اقدام اصلاحی استخراج می‌کند و خود استخراج نیز audit می‌شود.
- تشخیص اختلال و هشدار از پایش پایگاه داده، دیسک، حافظه، load، صف و dead-letter استفاده می‌کند. رخدادها قابل ثبت، رفع، تحلیل علت و ثبت اقدام اصلاحی هستند.
- پشتیبان رمزنگاری‌شده، checksum، تأیید صحت و اسکریپت restore موجود است. وضعیت پشتیبان و سلامت صف در شاخص آمادگی بازگشت استفاده می‌شود.
- عدد ۹۹ درصد فقط از نمونه‌های واقعی `service_health` محاسبه می‌شود؛ بدون نمونه، هدف محقق‌شده اعلام نمی‌شود. اثبات SLA تولیدی، میزبانی داخلی و failover مرکز داده به استقرار و اندازه‌گیری واقعی زیرساخت مقصد وابسته است.

## لاگ‌های الزامی

- ورود، خروج، ورود ناموفق، MFA، تغییر رمز، مشاهده پرونده، مشاهده/دریافت سند، بارگذاری، حذف و بازبینی سند، تغییر وضعیت، پیام، عملیات پرداخت و رسید، درخواست API، تغییر نقش، ایجاد کاربر، تنظیمات مدیریتی و رخدادهای امنیتی در لاگ دامنه مربوط ثبت می‌شوند.
- همه درخواست‌های `/api` با شناسه درخواست، کاربر احراز‌شده، method، path، status، زمان پاسخ، IP و زمان در `api_request_logs` ثبت می‌شوند.
- صفحه گزارش امنیتی، audit زنجیره‌ای و درخواست‌های API را با کنترل نقش یکپارچه نمایش می‌دهد.
- تغییر رمز از API و UI پروفایل، با بررسی رمز فعلی، سیاست رمز قوی و MFA فعال کاربر انجام می‌شود و موفقیت یا شکست آن audit می‌شود.

## بایگانی و دسترسی

- کاتالوگ بایگانی بر اساس شماره داخلی پرونده، نوع خدمت، متقاضی، مشخصات ثبتی ملک، وضعیت و زمان بایگانی از `GET /api/admin/archives` ارائه می‌شود.
- مالک پرونده به سابقه خود دسترسی دارد. دسترسی کارکنان به پرونده بایگانی‌شده زمان‌دار و مبتنی بر درخواست است؛ مجوز `view` و `export` جداست و حداکثر یک سال اعتبار دارد.
- تأیید مجوز فقط توسط مدیر عملیات یا مدیر سامانه‌ای ممکن است که نشست او با MFA تأیید شده باشد. مدیر نمی‌تواند درخواست خودش را تأیید کند.
- API مشاهده پرونده، گزارش HTML، CSV و دریافت سند بایگانی‌شده مجوز معتبر را مستقل از UI enforce می‌کند. مشاهده و همه استخراج‌ها audit می‌شوند.
- UI مدیریت بایگانی برای نقش‌های مجاز فهرست پرونده، ثبت درخواست، وضعیت درخواست و تصمیم مدیر را به‌صورت RTL ارائه می‌کند؛ ناظر همچنان فقط‌خواندنی است.
