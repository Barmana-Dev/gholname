# شواهد پیاده‌سازی صفحه ۳۲

## دامنه بررسی

صفحه ۳۲ فایل طرح توجیهی به‌صورت تصویری و متنی بازخوانی شد. این صفحه چک‌لیست ۱۵‌گانه پنل کاربر، ۱۰‌گانه پنل کارشناسان و ۱۵‌گانه پنل مدیریت را تعریف می‌کند. تطبیق با کد و بخش «پیوست ۱» در `PDF_LINE_BY_LINE_AUDIT_FA.md` انجام و نتیجه در فایل ممیزی اصلی به‌روز شده است.

## شواهد اجرایی

- پنل کاربر: ثبت‌نام و ورود امن، پروفایل، انتخاب خدمت و فرم اختصاصی، آپلود نسخه‌دار مدارک، رهگیری، اعلام نقص، پیام پرونده، شکایت و پیوست، سابقه تغییرات، اعلان قابل خواندن، پرداخت رسمی کنترل‌شده، رسید الکترونیکی و خروج امن در UI و API موجود است.
- پنل کارشناس: فهرست پرونده بر اساس ارجاع فعال محدود می‌شود؛ مشاهده مدرک، ثبت نظر و گزارش، اعلام نقص، درخواست مدرک، ارجاع داخلی کنترل‌شده، ثبت نتیجه و مشاهده سابقه موجود است. هیچ API برای حذف سابقه اصلی ارائه نشده و trigger دیتابیس حذف مستقیم تاریخچه را نیز رد می‌کند.
- پنل مدیریت: مدیریت کاربران و نقش‌ها، کارشناسان و ارجاع، خدمات و تعرفه، پرونده و مدارک، پیام و شکایت، پرداخت و استرداد، گزارش عملکرد/ریسک/امنیت، دسترسی، صف API و audit log از مسیرهای نقش‌محور موجود است.
- کنترل دسترسی UI از capabilityهای بازگشتی API استفاده می‌کند و API علاوه بر نقش، مالکیت پرونده یا ارجاع فعال را برای داده‌های پرونده اعمال می‌کند.
- ایجاد تراکنش واقعی همچنان به PSP رسمی و حساب حقوقی کارگزاری وابسته است؛ سامانه تراکنش یا رسید ساختگی ایجاد نمی‌کند و فقط پرداخت موفق قطعی را قابل رسید می‌داند.

## آزمون صفحه ۳۲

`server/src/page32.test.ts` مالکیت پرونده و رسید، محدودیت ارجاع کارشناس، نوع پیام و تغییر وضعیت مجاز، تفکیک دسترسی‌های مدیریتی و نبود مجوز حذف تاریخچه برای تمام نقش‌ها را بررسی می‌کند.
